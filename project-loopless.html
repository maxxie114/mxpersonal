LoopLess

A browser agent that remembers successful action sequences and tests whether it can reuse them on a later run.

Why run a task twice?

On a first run, the agent has to discover how to complete a task in a browser. On a repeat run, it can try a previously successful sequence of actions. Comparing the two reveals where experience saves work and where a page still needs fresh reasoning.

What I worked on

I improved the agent’s self-improvement loop and contributed fixes to the running application. The project uses Stagehand with Browserbase, stores reusable sequences in Redis and records evaluation traces in Weave.

Reading a trace

The useful comparison starts with whether the task succeeded. From there, a reviewer can compare the actions, model calls and time spent on cold and warm runs. A shorter sequence is useful only when it reaches the intended result.
